# Rendering backends

**Source of truth for the code:** [`app/src/draw/mod.rs`](../../app/src/draw/mod.rs).

## A backend is a whole pathway

A **backend** is one pipeline together with the actor kinds built for it.
Backends are mutually exclusive, and which one runs is decided **once at
launch** — not per camera, not per object, not per actor.

Two techniques that composite differently cannot share a frame correctly.
Choosing once removes that entire class of interop question rather than
answering it one case at a time.

A pathway that cannot run on the machine **refuses**. It does not quietly fall
back to another, because the pathways composite differently: a substitution shows
a picture that is wrong and says nothing about it. Wrong and silent is worse than
not starting. See `draw::probe`.

## Actor kinds belong to a backend

How a dataset is best mapped onto GPU primitives depends on the pipeline. A
pathway that merges spheres into one mesh shares no geometry code with one that
instances a single sphere per atom or raytraces analytic ones — they are not
doing the same thing.

So actor kinds live inside the pathway directory. A kind a pathway cannot do is
simply absent from the registry and refused by name, rather than drawn wrongly.

**The exceptions are deliberate.** Chemistry — an element's radius and its
conventional colour — is a fact about the periodic table, not about a pipeline,
so it sits in the shared layer. So does the ball-and-stick tessellation and the
cartoon sweep: an opaque ball-and-stick is an opaque ball-and-stick whatever
draws it, and the shared-layer rule is about what genuinely differs between
pathways, not a prohibition.

## Why generation is not a kind

There is no `cartoon` actor kind. A ribbon is generated by
[a filter](filters.md) and drawn by `surface` or `medium` — or by both at once.

Had it been a kind, it would have generated a ribbon *and* drawn it, so showing
one as a medium rather than a lit surface would need a `mode` parameter
duplicating `surface` against `medium` inside a third place. That is the `N * M`
shape the filter split exists to prevent.

## The seam stays with one pathway behind it

`draw` is the shared layer and `draw/default/` is a pathway directory, even
though `default` is currently the only one. Which technique iris3d should settle
on is still an open question, and flattening the two together would answer it by
accident.

What has gone is only the machinery for reconciling *two pathways at once* — a
`Backend` enum, a `--backend` flag, and a `shared` flag on a kind. The directory
seam is not that machinery.

## Alternatives tried

Both are recoverable from git history.

- **A plain `Mesh3d`-per-actor baseline on the standard pipeline.** It could not
  compose a mesh with a volume correctly, which is the thing this project is
  actually for.
- **A `bevy_solari` raytracing pathway.** No transparency and no volumes, and
  having to keep every kind working under both was shaping the design of things
  that had nothing to do with raytracing.

## What the shared layer holds

It draws nothing. It holds what makes an actor out of date (`Dirty`, which grades
invalidation because rebuilding geometry and changing a colour are not the same
cost), how a bound handle resolves to an array, how values become colours, and
what order the per-frame work runs in.

What each kind needs is **declared, not assumed**: a kind states its inputs as
array parameters, so a client is told that `points` wants `float32 [n, 3]` rather
than having to name an array "positions" and hope.
